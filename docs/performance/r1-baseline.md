# R1 performance baseline

The committed `benchmarks/r1-engineering-reference.json` artifact is historical/reference-only evidence from an older head on Node 24. Its overlapping compilation phases, model-export surrogate, and heap-delta-only memory evidence are superseded. The retained numbers have not been rewritten. It is neither current-head Node 22 evidence nor an approved budget or R3 comparison baseline.

Capture uses two warmups and five measured runs per synthetic fixture by default. `PERF_WARMUPS` (0–10), `PERF_RUNS` (1–20), and `PERF_OUTPUT` may override those values. The v2 artifact retains the actual captured Git head/runtime, raw records, context, phase summaries, requested/reached horizon and completed status. Incomplete/unavailable/thrown executions reject capture, including warmups and scaling probes. CPU is aggregate process user/system execution time, not a financial value or budget. Absolute sampled heap after execution/diagnostic collection is retained alongside signed heap delta; the sample is not a peak. Local Node and browser-main execution are `not_metered`; no zero-dollar provider cost is fabricated.

Primary Golden/realistic/stress records remain separate from four bounded scaling probes (12/24 months × two supported recurring-operation/entity scales). Each probe retains horizon, actual recurring-operation count and model entity count. Golden is unchanged. Realistic adds distinct P08 assumption bindings, multiple income-termination events, accounts/positions, monthly investment purchases/transfers, and mortgage extra-principal dependencies. Stress scales those supported mechanics over 180 months. The coverage inventory links executable evidence: root forecasts are measured by capture; the declared lower-return intent is exercised by a CI comparison request and is explicitly not a measured comparison benchmark. Earlier-retirement comparison and contention-policy coverage are not claimed. Timing never establishes a correctness threshold or an approved p95 budget.

Browser-main diagnostics are interactive/in-memory and available in `Settings > Advanced`; they are not a retained representative-device baseline. Attribution expires after the matching forecast commit; unrelated navigation, charts and explanation work are not attributed to that forecast. React/chart timings are profiler-dependent and display as N/A when unavailable. Forecast transport serialization is explicitly `not_applicable`: there is no worker/server transport. Model export is not a surrogate. Server/cloud execution remains `not_implemented/not_measured`; placement recommendations are deferred until approved budgets exist.

GitHub ordinary CI provides bounded deterministic evidence: realistic/stress application smokes complete a one-month request, a targeted two-month compiled-engine check exercises transfers and extra principal, and scaling tests check matrix declarations, counts, coverage and one-month compilation without forecasting the full probes. Injected application/engine-owned clocks and sinks prove diagnostic failure isolation; E2E retains normal Advanced/N/A/context and stale-attribution coverage without corrupting global browser timing APIs. Ordinary CI does not execute the full 24-month realistic, 180-month stress or 12/24-month scaling forecasts, and it does not establish timing/resource evidence or budgets.

Codex does not run capture, tests, typecheck, builds, Playwright or validators. After ordinary CI is green, the existing manual `engineering-validation` workflow with profile `performance` on Node 22 owns full primary/scaling executions and uploaded timing/resource artifacts/history. `benchmarks/capture.ts` enforces full requested-horizon completion through `requireCompletedPerformanceForecast`; bounded CI smoke completion does not prove full-horizon completion. The first external current-head performance smoke should use warmups=0 and runs=1. Current-head repaired evidence is pending that external run. No latency, memory, throughput, cost or convergence budget is established by this repair.
