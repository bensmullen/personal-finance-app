# U1B design-to-production workflow — PM approved 2026-10-30

**Status:** Approved product/design planning gate; not an implementation or financial-model authorization.
**Owners:** ChatGPT (architecture, design, QA), Codex (approved UI implementation), PM (design/merge/UAT).
**Traceability:** U1B/D1/D2 UI acceptance [#120](https://github.com/bensmullen/personal-finance-app/issues/120); implementation checkpoint [#187](https://github.com/bensmullen/personal-finance-app/issues/187); D2 source integration [#149](https://github.com/bensmullen/personal-finance-app/issues/149); investment scheduling [#100](https://github.com/bensmullen/personal-finance-app/issues/100).

## Mandatory five stages for substantial UI work

1. **User-journey inventory:** Identify comprehensive lifetime-planning user goals and financial use cases; group them by intent into top-level pages only after mapping capabilities, dependencies and task order. Define intended user, principal question, supported data, action, next destination, and unsupported outcome. Inspect existing D1 and live D2 contracts before calling an input or result modeled.
2. **Approved visual contract:** Create a coherent visual system and page designs, preferably incrementally by journey. Every design must explicitly cover **visual hierarchy, information density, typography, layout, language, navigation, states, responsive behavior**. Specify concise first-screen insight, single primary action, progressive disclosure, clear edit ownership, source limitations, and keyboard/touch behavior; include approved desktop 1440×900 and mobile 390×844 render targets. Betterment informs the calm top-level dashboard mood, Robinhood the sleek focused detailed views, and Empower the useful Overview dashboard. They are reference inspiration, not permission to copy assets or financial behavior. PM reviews cohesive designs rather than pixel-level fixes.
3. **Bounded implementation:** A validated GitHub V3 issue links the approved design and authoritative financial specs; Codex implements only resolved paths/decisions, reusing existing components and model selectors. No second financial kernel, fabricated retirement streams, unsupported trade execution, or redundant long-horizon forecast payloads.
4. **Independent visual/semantic QA:** After exact-head CI, ChatGPT (outside Codex) inspects a real running app and production/reference captures at both target sizes, 200% text, touch/keyboard, current/stale/partial/pending/unsupported/error/zero states, and a long forecast. Compare user journeys, hierarchy, whitespace, comprehension, chart interactions and provenance; return a narrow same-issue repair if needed. Screenshot generation or passing CI does not demonstrate usable visual parity.
5. **Uncoached PM UAT:** The PM tests normal outcomes without click-by-click coaching. Final U1B acceptance under #120 requires usable D1 and supported D2 functionality, connected authoring-to-forecast workflows, source-exact results and honest gaps. Technical PR merges are checkpoints, not U1B completion.

## Source and scope boundaries

Planning may visualize supported retirement events, requested age-90 timing, balance and liquidity evidence; an unavailable by-source V6 chart must be explained without filling the primary view with a pseudo-chart or guessed pension/SSA/withdrawals. Investment buying, selling, transfers, dividends, contributions and retirement withdrawals are hypothetical planning/forecast inputs, **not execution of securities trades**. Before adding controls or assuming taxation, audit existing D1/D2 domain sources for trade date/price, holdings/lot selection, basis, capital gain, wrapper/distribution treatment, withholding, settlement, bank transfers, funding priority, tax-year interactions, RMD and replay provenance. Reuse #100/#146/#149 as existing ownership; create additional authorized issues only for independently scoped gaps after approved architecture.

## Design gate and dependency policy

Before a substantial UI design or task-contract approval, use real screenshots and supported source data to confirm the proposed first screen answers a user question without technical clutter. Cross-screen planning groups goals/journeys before page design; only then assign coherent serial implementation slices for shared JSX/CSS. Do not require all pages to be designed simultaneously. D2 engine work may proceed independently, but source/identity-safe read models and U1 handshakes must be proven before D2 UI claims complete. The final uncoached U1B/D1/D2 UI gate remains #120, with D2-D source/integration acceptance independently retained at #149.
