## D2 parallel-implementation CI seam

1. **Isolated D2-A/B/C domains:** The D2 prep catalog's 55 variants and 24 conditional effects are test-only, **not** executable end-user support. Future disjoint `src/simulation/d2/**` domain changes are routed by today's verification planner as any `src/**` change: architecture + typecheck + unit + build + **all four E2E shards**. This is conservatively safe but potentially unnecessary expense for unreferenced modules. Do **not** weaken routing on the assumption that a module is isolated. A future optimization should prove an import/dependency boundary, fail closed for runtime/reexport/shared-contract changes, retain a periodic full verification escape hatch, and measure runner-minutes versus missed risk.
2. **Shared D2 contracts and execution integration:** No concurrently active D2 domain owner should write U1B's `ui/**` or `app/**`, the application compiler/forecast read model, tax/settlement, or shared simulation state. A single separately authorized integration owner coordinates public identity, effect timing, funding, basis, limits, capabilities, tax and result shape, and updates corresponding UI tests in the same integrated PR only when semantics truly change. Final D2-D household/UAT follows integration and accepted U1; domain fixture green CI is not a UI acceptance claim.
3. **Spec/test coupling:** D2 handoffs should enumerate (a) unit/domain expected effect fixtures; (b) scenario-specific supported versus unsupported capability boundaries; (c) existing E2E scenarios now intentionally affected; (d) one cross-seam smoke for ownership, no double counting, stale-result truthfulness and save/reload when shared execution changes. Never have tests infer their *expected* result from the implementation under test. Retire an obsolete negative assertion only after its replacing supported behavior is independently verified.
4. **Documentation debt found:** `docs/development/d2-prep/follow-on-plan.md` still names U1 **#94**, whereas the current milestone register designates U1 final gate **#120**. The D2 prep plan also calls **#103** the active distributions owner, but #103 is currently **closed** as planning-only while the milestone register retains it in the D2 gate. Resolve the live ownership/roadmap reconciliation **before authorizing D2 distribution implementation**; do not treat either historical issue closure as financial capability completion.

## Validation and acceptance

This audit is a scoped source/policy review, not a newly executed browser UAT or semantic certification of future D2. The two test-only fixes are subject to latest-head selected GitHub Actions CI: with `e2e/**` changed, typecheck/build/E2E are selected, and all four Playwright shards plus aggregate test must pass. Record whether splitting R4 affects fixture cost or max shard latency; a green run alone does not prove the split reduced total runner-minutes.

**No changes to:** financial calculation, forecast data selection, UI components, CI workflow, test fixture expected economics, D2 domain runtime, or the D2 authorization gate. A further rewrite of the full 2,000+-line legacy E2E file is explicitly out of this audit's scope. The active AL-003/AL-004 and candidate #144 remain the learning-policy references.
