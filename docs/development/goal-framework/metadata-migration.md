# Operational issue metadata migration

## Shadow delivery under issue #364

The milestone issue register remains the delivery allocation authority. The traceability workflow reads both open and closed GitHub issues and publishes `issue-metadata-shadow-<head>` with an offline equivalence report and its live comparison. The checker supports `--export` for the full legacy import, `--offline-shadow` for reproducible comparison, and `--live-shadow` for the bounded, issues-read inventory. The reports identify each obligation by issue, kind and canonical digest. The live report adds the digest of the observed full body and a list of uncovered open issues. An uncovered issue fails the workflow. Reports omit raw issue bodies, titles, labels, credentials and personal data.

The import preserves registered owner stages, first mandatory gates, dependency edges, controlled requirement IDs, gate lists and acceptance wording. Administrative issues retain their original classification. Consolidations retain the entire chain and provenance, including the #99 → #94 → #120 D1/U1 obligation and #103 → #146 D2 obligation. Imported authority reports no operational goal or approval for a historical issue. Closure and a matching shadow report carry no acceptance or execution authority.

## Rehearsal and activation boundary

1. **Export and compare.** Pin the register and preserve the complete issue inventory with full-body digests at export. Review the exact-head reports and test evidence. Use a reviewed immutable import as the baseline. Keep the goal-plan checker, live workflow, milestone policy and dispatch on register authority during shadow.
2. **Prepare a reviewed cutover.** Obtain explicit PM approval after independent review. Suspend admissions under an authenticated fence and confirm a fresh complete inventory under the same fence. Review each body change since export and bind the approved reconciliation to the exact replacement digest. Establish writer permission, active-grant protection and a provider fence that covers all issue-body editors. GitHub REST GET followed by PATCH has a race and cannot supply that guarantee. The current delivery contains an offline adapter contract and no live writer.
3. **Apply only reviewed batches.** The durable journal holds at most 64 changes with issue identity and before/after body digests. Bind it to repository, authorized writer fence and the independently retained reviewed record set. An active grant's saved issue body stays byte-for-byte intact. Resume a batch by verifying that the observed body matches the before or after digest. Require a guarded compare-and-write for pending entries, then re-fetch each saved body. Pause on permission loss, a missing issue/page, an active grant conflict, a third digest or changed readback. Stamp approval and active-grant data from their authenticated source.
4. **Activate the consumers together.** Use `projectMetadata` against a complete current observation set, the immutable import and authenticated task/goal-control and admission sources. Verify the approval reference, task revision and phase allocation against those sources. Require an independently verified acceptance record for completing obligations. Use the traceability projection for live coverage and publish its generated snapshot with repository and observation time. The plan checker accepts that projection via `--allocation-snapshot` and can independently run `--live-contracts` with the actual V3 parser. At dispatch, re-fetch the saved V3 body and validate it through the hook together with fresh live allocation and actual branch/receipt evidence. Offline snapshots and syntactic checks carry no readiness authority. No environment toggle or issue-body field activates this rollout.
5. **Roll back with current admissions.** Freeze admission again. Reconcile the fresh inventory with the durable list of admitted task allocations, including closed tasks and anything created after cutover. Project the surviving legacy obligations plus all admitted allocations into the rollback register. Verify every gate list, dependency, requirement and consolidation before reactivating register-backed consumers. Restore from this reconciled result. Preserve issue bodies and active grants, and resume admission only after the authority change is complete. A replay of the original export alone would omit post-cutover obligations.
