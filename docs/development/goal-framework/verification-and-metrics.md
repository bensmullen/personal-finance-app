# Verification, evidence and performance measurement

Owner: goal #362, with acceptance on each original GF task. This is an implementation/test reference, not a record of tests already executed. No native compatibility, household completeness, performance improvement or quota visibility is established by this document.

## Verification levels and cost

| Level | Trigger and scope | Owner and cost boundary |
| --- | --- | --- |
| L0 plan integrity | This package changes: IDs, graph, register allocation, requirement/test coverage and saved V3 syntax | Deterministic stdlib check; no model, browser, package install or financial simulation |
| L1 offline behavior | Changed controller/contracts: table-driven pure tests, fake GitHub/events/clocks, temporary Git remotes and receipts | Ordinary selected CI; no real credentials, native agents or external services |
| L2 integration assurance | Changed lifecycle/evidence/adapter boundary: preserved V3 tooling tests, inventory checks, bounded browser/household profile | CI/engineering-validation, exact head; no active coding model supervising waits |
| L3 native compatibility/pilot | Adapter version or phase activation: minimal actual local/cloud smoke; supervised and final approved multi-task pilots | Separately bounded goal/pilot budget; not every PR or routine no-change event |
| L4 targeted mutation/release | Material financial/source/replay/control change or release gate | Isolated targeted/incremental run; broad suites only when justified, with ceilings and survivor classification |

No full framework pilot or mutation sweep runs for every issue edit. Reuse exact matching evidence by reference; changed contracts, code, fixture identity or integration state invalidate affected evidence. Existing selected product CI remains mandatory. Lightweight means appropriate scope and deterministic checks, not weaker acceptance.

The plan checker must reject malformed mappings, unknown requirement/test IDs, missing ownership, dependency cycles and stage/register disagreement. Its optional live mode re-fetches saved issue bodies and calls the repository hook's actual `validate_task` parser (isolating the parser functions, not invoking hook lifecycle). It reports body digests and observed revisions. It never authorizes writes or asserts local readiness. Revalidate again at actual dispatch because issues are mutable.

## Evidence record and audit template

Store exact repository/PR/head/integration identity, goal/task/fixture revisions, selected profile/check inventory, each job/shard/attempt outcome, artifact references/digests, independent reviewer identity/disposition, unresolved findings, and actual resource/telemetry coverage. No real household payload, secrets or full conversation transcript. Existing CI artifact retention may expire: preserve compact acceptance metadata and durable links in the original issue, and mark unavailable evidence rather than assuming it still exists.

At each substantive audit write: verdict; accepted requirement IDs; outstanding defects with evidence; exact PR/head and all selected checks; approved versus proposed changes; scope/dependency changes; next authorized step; metric coverage. Re-fetch/parse a revised operative issue. #362 gets phase exit, pilot/metric and activation summaries, not every poll. Never close a phase solely because its issues were closed or its code merged.

## Metrics and baseline protocol

Baseline starts NOT MEASURED. GF-05 instruments collection; before P3, capture up to five recent comparable accepted manual-V3 tasks where reliable evidence exists, plus prospective measurements when old telemetry is absent. Compare the first three to five pilot outcomes by risk/size class; report actual n, medians/ranges, coverage and paused/censored work. Small samples are directional evidence, not causal proof. No retrospective token estimates presented as observations.

| ID | Definition / denominator | Source and interpretation |
| --- | --- | --- |
| GF-M01 | Total comparable observed coordinator + worker usage per independently accepted capability slice | Native usage observations/reservations; keep units/pools separate, include rejected attempts, report coverage. PR count is not capability size. |
| GF-M02 | Coordinator share of observed total usage | Same comparable unit/pool only; unknown coordinator data prevents a complete efficiency claim. |
| GF-M03 | Routine PM interventions per accepted outcome; separately decision/UAT interventions | Authenticated events/audit log; target fewer routine steps, never fewer necessary decisions. Initial 50% reduction is an experiment target, not a safety waiver. |
| GF-M04 | Ready-to-accepted-merge lead time, with PM wait/CI/implementation/review components | Timestamped state events; report paused/censored tasks rather than excluding hard work. |
| GF-M05 | First-pass accepted outcomes / reviewed outcomes | Independent first publication review; distinguish actual code acceptance from green CI only. |
| GF-M06 | No-edit missing-scope starts and same-root repair attempts per task | Original issue/lifecycle records; track cause and whether census existed. |
| GF-M07 | CI runner-minutes and critical-path latency per accepted outcome | All attempts/jobs, including cancelled work where available; do not trade coverage for apparent speed. |
| GF-M08 | Unauthorized writes/merges, escaped material defects and UAT-bypass incidents | Verified incidents, not assertions that absence of observation proves perfection; zero known safety violations is required. |
| GF-M09 | Independent review backlog age, ready-work parallel occupancy and ownership-conflict rate | Scheduler/events; productive parallelism means more accepted work, not maximum fan-out. |
| GF-M10 | Handoff/event bytes, redundant reads, no-change model calls and evidence reuse coverage | Structural counters; verify bounded references/linear growth and no lost decisions, not arbitrary prompt-size caps. |

Each metric record includes window/cohort, source/unit, observed/estimated/unknown quality, numerator/denominator, coverage, n and evidence refs. Missing values are null with reasons, not zero. Do not equate tokens/messages/quota percentages or double-count shared Work/Codex allowance. Subscription promotions/limits and model names must be checked at execution time rather than encoded here.

## Acceptance targets and improvement discipline

Hard gates: no known authorization/merge/UAT bypass; complete applicable selected evidence; all required household cases and independent reviews before UAT; safe recovery and actual native compatibility for claimed modes. Efficiency targets: fewer routine PM interventions, scope restarts and repeated repairs, lower total usage and comparable lead time without more defects. No fixed promised savings or new product performance SLA is invented.

GF-09 proposes an experiment only when evidence changes: hypothesis, affected task cohort, bounded cost, safety invariants, comparison and rollback. Existing learning governance decides candidate promotion. Changes to shared controls require an independent framework PR; the agent cannot loosen its own guards to improve the score. A failed experiment is retained as evidence and reverted safely, not hidden from metrics.
